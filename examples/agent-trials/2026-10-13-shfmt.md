# Native OpenCode control: add shfmt to arkade

This is a workflow control for the experimental `arkade-add` quality task,
**not** a RigMark Quality suite receipt. It tests whether the same models can
complete the ordinary coding task with a terminal, the repository's
`AGENTS.md`, and normal feedback from builds and tests.

Two fresh Slicer OpenCode VMs each cloned `alexellis/arkade` and checked out
`e5215097ce8d9340af060412663f7c7130c594dd`, before shfmt was added.
Both installed Go with `sudo arkade system install go`. OpenCode used Toilgate;
the primary and small model were pinned to the named contender in each VM.
The prompt was identical:

> Add shfmt from mvdan/sh to arkade get. Follow AGENTS.md.

| Model | Initial agent run | Initial outcome | Review follow-up | Final outcome |
| --- | ---: | --- | ---: | --- |
| DeepSeek V4 Flash 0731 | 2m47s | Five-platform downloads, package tests, and independent URL acceptance passed; one README line had trailing whitespace | 7s | Diff clean; Go code unchanged |
| GLM-5.3-Flash | 3m03s | Five canonical-platform downloads and package tests passed; independent check found missing `amd64` and Linux `arm64` CLI aliases | 1m27s | Aliases fixed; independent URL acceptance passed; diff clean |

Both agents used `./hack/test-tool.sh shfmt` to check the downloaded Linux,
macOS, and Windows binaries. The independent acceptance test was applied only
after each agent stopped. It checks release URLs at two versions, architecture
aliases accepted by arkade, and that existing catalogue entries were not
changed. The final Go files had no `gofmt -l` output, and `git diff --check`
was clean. Times are the `opencode run` wall times; VM provisioning and Go
installation are excluded.

Protocol 0.6 gave the suite's `arkade-add` model only restricted typed file
tools, an offline snapshot, and a narrowly specified edit. Both models missed
an independent URL case in their one-shot protocol 0.6 attempts. Protocol 0.7
uses a native OpenCode session in a fresh Slicer VM, with the full checkout and
the short prompt above. Its first verified DeepSeek attempt finished in 185s
and passed the independently applied Go, URL, README, and formatting checks.
These observations show that the protocol 0.6 result was sensitive to the
harness and feedback loop; it is not a general failure to add shfmt with a
coding agent.
